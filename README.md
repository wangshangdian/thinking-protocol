# thinking-protocol · 底层思维集合

原话、快速使用：
以下这几句作为你的底层思维：
- 1有重要的需要和我确认的先问我，持续问我，直到你认为我的需求已经够具体，防止你因为模糊而脑补。
- 2先客观分析我说的对不对，我是探索者而不是大师。
- 3我喜欢探究原理的原理，计划之前先制定计划的计划，重要的地方我就喜欢这么思考。
- 4有时候我喜欢让ai说一些重要性高的延伸方向。
- 5毕竟我是探索者，有时我的思路是野路子，想要找正规军的思路或者方法。
- 6从顶向下设计，防止方向错误。
- 7先理清我的想法再做，防止一错再错。
- 8一个事情如果涉及到长远的使用，那么我喜欢支援未来与复利思维。 

> 一个跨项目复用的 Skill：**在信息不完备时，先定方向，再动手。**

## 它解决什么问题

模型的默认失效模式是「**顺从式幻觉执行**」：

> 收到模糊需求 → 自动补全成一个具体版本 → 高效地把它做出来。

看起来非常努力，实际上方向已经歪了。本协议用一组检查项把这个默认行为按住。

**方向风险 > 执行风险。**

## 三层原理

| 层 | 内容 | 学术对应 |
|---|---|---|
| 1 | 方向风险 > 执行风险 | — |
| 2 | 信息不完备时，先花低成本买信息，再花高成本执行 | Value of Information / EVPI |
| 3 | 不可逆动作杀死未来的选项，而未来需要选项 | Real Options |

## 八项协议

| | 协议 | 一句话 |
|---|---|---|
| P1 | 澄清与提问 | 需求不清楚不是让用户想清楚，是**模型**承担提供信息的责任 |
| P2 | 客观裁定 | 先判对错，再给方案；两级对照，防讨好式同意 |
| P3 | 第一性原理 | 不是找「本质」，是找**硬约束**；自顶向下 + 自底向上回验 |
| P4 | 延伸方向 | 硬限额 3 条，按「是否命中绑定约束」排序 |
| P5 | 正规军对照 | 自创方法先去找官方版本（名字 = 全部文献） |
| P6 | 复利资产化 + 文件化 | 子任务靠**文件**传递；版本控制是底座 |
| P7 | 支援未来 | 边界由**不可逆性**定义，不由难易定义 |
| P8 | 模型分工与纠偏 | 「怎么问」比「问谁」重要一个数量级 |

## 启用门槛（先分档，别仪式化）

| 档 | 条件 | 走哪些 |
|---|---|---|
| 轻 | 单步 / 纯查询 / 可逆无成本 | 直接答 |
| 标准 | 多步任务、要产出代码或文档 | P1 → P5（可精简） |
| 重 | 长期项目 / 含不可逆成本 | 全部 + P6 建骨架 |

⚠️ 把重型协议用在轻量任务上是**负资产**——过度仪式化会导致整个技能被弃用。

## 这么多内容，会不会太重？（不是）

加载是**分层**的，不是全部进上下文：

| 层 | 体量 | 什么时候付这个成本 |
|---|---|---|
| frontmatter description | ~250 字 | 常驻（这就是触发器本身） |
| `SKILL.md` | ~7 千字 | **只在技能触发时**读一次，之后就在上下文里了 |
| `references/` ×8 | ~2 万字 | **按需**读。不读就不花钱 —— 它是**期权**，不是负担 |

⇒ 真正每次都付的只有 `SKILL.md` 那约 2k token。references 存在本身不产生成本。

**新项目不用搬任何东西**：技能装在用户级目录，所有项目自动可见。
往新项目里再抄一份协议 = 违反本技能 P6「单一事实源」（反模式 #14）。
新项目要做的只有一件事：

```bash
python scripts/init_project_docs.py <项目目录>
```

它会铺出 `docs/10-协作契约.md`，其中「**★ 短锚**」就是你要的**标题 + 一句话**那一层。

⚠️ 那 9 条短锚在 `10-协作契约.md` 与 `子任务/_模板-开题包.md` 里**各存一份、逐字相同** ——
这是**有意的**（开工包必须自包含）。代价是双份维护：
**改一处必须同时改另一处并升版本号**，否则两份静默发散。已加 `v1` 标记，对不上就是发散了。

## 已知失效条件

- **最重要的一条**：把它**仪式化**。每次回复都走完整八项协议 = 用户会弃用整个技能，比没有技能更糟。
- 判据：**用户是否在往前走？** 如果流程让你不断提问、迟迟不出结果，就是仪式化了。

## 停止规则（什么时候该收手）

> ⚠️ 已观察到的失效模式：「**更强的一方指出遗漏**」这个序列**不收敛**。

每换一个更强的模型 / 更严的评审，它都会找出新的遗漏，因为它知道得更多。
照单全收 ⇒ 研究精力持续花在「优化一个还没决定要不要建的引擎的涡轮型号」上。

三条规则：① 开工前先写否决条件 ② 判据事后不许改 ③ 沉没成本不参与判断。
**停手 ≠ 失败**。详见 `references/06` §四。
