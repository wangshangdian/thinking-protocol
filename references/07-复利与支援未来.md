# 07 · 复利与支援未来

> 这两条是**一对**，不是一条。搞混会把"生产资产"和"保住本金"混为一谈。

| | 复利思维（资产化） | 支援未来（跨期可逆性） |
|---|---|---|
| 回答的问题 | 这次输出怎么**变成资产**？ | 这次动作怎么**不烧掉未来**？ |
| 面向 | 动作（生产） | 时间（保全与转移） |
| 判据 | 三个月后还能用吗？ | 一年后的我会感谢，还是骂我？ |
| 缺了的后果 | 每次都从零开始，纯成本 | 一次不可逆的错，前面全白做 |

**关系**：复利是把收益**存进**未来，支援未来是**别把本金烧掉**。一个开源，一个保本。

---

## 一、复利思维（资产化）

**核心问句：这三个月后还能用吗？**
- 能用 → 把它**结构化**成下面某种形态，而不是留在对话里
- 不能用 → **明确标记为一次性消耗**，不要假装它是资产

### 资产的六种形态（输出尽量往这些形态上靠）

| 形态 | 例子 |
|---|---|
| 可复用模块 / 脚本 | 一个能复用的 fetch 库、验证库 |
| 数据集（带正确时点） | 落盘的 Parquet + 数据字典 + 时点说明 |
| 结论 + 失效条件 | 可回查的裁定，带"什么情况下作废" |
| 模板 / 检查表 | 开工包模板、自检清单 |
| 通则 / 坑（编号化） | M 编号通则、坑编号 |
| 可粘贴短锚 | 跨会话、跨项目继承用 |

### 反模式
- 把「写了文档」当成资产化——文档没人读、不能执行，也是成本
- 一次性脚本不落盘、不命名、不留参数说明
- 结论不带失效条件（下次还会踩同一个坑）
- 用「以后再整理」推迟结构化（以后 = 永不）

## 二、支援未来（跨期可逆性）

**核心问句：这个动作会缩小还是扩大未来的选项空间？**

### 三问
1. 它会**不可逆地消耗**什么？
2. **未来的我需要什么**？我留了，还是堵了？
3. 一年后的我看到这个决定，会觉得**被支援**，还是被埋坑？

### 不可逆消耗清单

| 类型 | 不可逆的东西 |
|---|---|
| 资金 | 爆仓（**吸收态**）、一次性大额支出 |
| 🚨 **凭据** | 密钥 / token / 私钥 / 身份证件照 —— **一旦同步上云或进了版本库，就收不回来了** |
| 数据 | 删库、覆盖原始数据、丢失时间戳 |
| 信任 | 对外发出不可撤回的消息 / 承诺 |
| 时间 | 在错误方向上堆的工期（沉没成本 + 机会成本） |
| 结构 | 引入无法移除的耦合、锁死的技术选型 |
| 身体 | 睡眠 / 健康——**最常被忽略的一类** |

### 四个机制
1. **保留余量（slack）**：任何不可逆投入 ≤ 可承受范围。满负荷系统没有弹性。
2. **可逆优先**：两条路都能到达时，选可逆的那条。
3. **消耗转资产**：把一次性支出改造成可复用的（与复利接上）。

### 4. 凭据与隐私：把暴露面降到最小（2026-09-18 补入）

**为什么这条属于 P7 而不属于"安全常识"**：因为它的失败模式**恰好就是不可逆**——
一条明文密钥被同步到云端之后，你无法"撤销同步"；被推进 git 之后，即使删掉文件，
它仍然留在历史里（以及任何已经 clone 过的人那里）。**唯一的补救是轮换，而轮换有真实成本。**

三条硬规则：

| # | 规则 | 落地动作 |
|---|---|---|
| 1 | **凭据放在"不同步、不入库"的位置** | 一个固定目录（如 `~/.workbuddy/secrets/`），并确认它在云盘同步范围**之外**、在 `.gitignore` 里 |
| 2 | **`.gitignore` 先行，而不是事后补** | 建库的**第一步**就写 ignore（密钥 / `.env` / `*secret*`），而不是等发现泄露了再补 |
| 3 | **外发前扫一遍** | 推公开仓库、发文件、贴对话之前跑一次密钥扫描（长十六进制串、`apiKey\|secretKey\|passphrase\|BEGIN PRIVATE KEY\|Bearer`）。**扫描是唯一能发现"我以为没放"的机制** |

⭐ **两条反直觉的**：
- **"只读密钥"也是密钥**。只读权限降低了损失上限，**不改变"泄露不可逆"这个性质**。
- **"私有仓库"不等于安全**。私有只降低了暴露概率，仓库仍可能被误设为公开、被协作者导出、
  被平台侧索引。⇒ 凭据的默认位置永远是**库外**，不是"库内但私有"。

⚠️ **已经泄露过怎么办**：不要试图"清理干净"，直接**轮换**。
清理历史（`git filter-repo` 等）只能减少二次暴露，不能撤回已经发生的暴露。

## 三、它解释了「授权分级」

为什么边界是**不可逆性**，而不是"难不难"？

> 因为**不可逆动作杀死未来的选项，而未来需要选项**。

- **授权分级** = 执行手段（什么时候必须先问）
- **支援未来** = 它的第一性原理

**推论（很反直觉但很有用）**：
- 「难」不是暂停的理由——一个很难但完全可逆的操作（重跑一次实验）可以直接做
- 「易」不是动手的理由——一个很容易但不可逆的操作（删一个文件、发一条消息）必须先确认

## 四、正规军对照

| 你的说法 | 正规军 | 出处 | 备注 |
|---|---|---|---|
| 支援未来 | **实物期权 Real Options** | Dixit & Pindyck 1994, *Investment under Uncertainty* | 不确定性下"等待"本身有价值；不可逆投资要付期权溢价 |
| 保留选项 | **可选性 optionality** | Taleb《反脆弱》 | 杠铃策略：大部分极保守 + 小部分极激进 |
| 留余量 | **保留冗余 slack** | 弹性工程（Hollnagel, *Resilience Engineering*） | 满负荷系统无弹性 |
| 可逆 vs 不可逆 | **单向门 / 双向门** | Bezos 2015 致股东信 | 双向门快速决策，单向门慎重决策 |
| 复利思维 | **资本化 vs 费用化（capex / opex）** | 会计学 | 把一次性支出转成可折旧资产 |
| 为什么要制度化 | **双曲贴现 hyperbolic discounting** | Laibson 1997 | 人天然偏向当下 ⇒ 支援未来**必须写成规则**，不能靠意志 |
| 资产复用 | **原子笔记 / 第二大脑** | Luhmann；Forte | 每条笔记都能独立复用 |

⭐ 最短版本：**复利 = 把产出变成资产；支援未来 = 别把本金烧掉。**

## 五、反例（真实翻车，可复用）

**1.「跑得快、策略好也难爆仓」**
隐含假设：加仓不会伤害未来的我。实测为**假**：
- 全仓模式下加仓会把**所有仓位**的强平价一起推向现价（"赚了加仓更安全"是错的）
- **爆仓是吸收态**——爆一次本金归零，数学上无法恢复

⇒ 正确结构：核心仓 + 彩票仓（≤ 总资金 5%，逐仓，允许归零）。
⇒ 通则：**止损距离 < 距爆仓距离 × 1/2**。

**2. 为了当期指标引入不可移除的耦合**
例：让主流程在运行时依赖一个不稳定的外部数据源，换取"看起来更实时"。
短期好看，长期锁死——未来每次改动都要绕它。
