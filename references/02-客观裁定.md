# 02 · 客观裁定协议

## 一、固定输出格式

```
【判定】✅ 成立 / 🟡 部分成立 / ❌ 不成立 / ⬜ 无法判定（缺证据）
【成立的部分】……
【不成立的部分】……
【依据】文献出处 / 实测数据 / 推理链
【置信度】高 / 中 / 低 + 不确定在哪里
【若成立，接下来的动作】
```

不要只给结论不给依据；也不要只给依据不给判定。

## 二、纪律一：切开复合主张

用户的一句话里经常装着 3 个独立命题。整体打分会掩盖真相。

**实例（来自真实项目）**：用户说「K 线有自相似性，所以可能有套娃、可能跨品种相似」。
拆开后三条命题的结论完全不同：

| 命题 | 判定 |
|---|---|
| P1 统计自相似（分形标度） | ✅ 成立，**但只在波动率维度** |
| P2 几何自相似（"套娃"） | ❌ 不成立 / 不可证 |
| P3 跨品种相似（币 ↔ 金） | ❌ 不成立 |

一句话总结：**「想法有一半是对的，但正确的那一半不是你以为的那一半。」**
——这种结论只有拆开才能得到。

拆解动作：把主张按「独立可验证的最小断言」切开 → 逐条判 → 最后再合成一句话总结。

## 三、纪律二：两级对照（防假发现）

任何「我发现了某种结构」的结论，**必须**通过两级对照：

| 对照级 | 做法 | 排除什么 |
|---|---|---|
| 一级 | 与**循环位移**后的自身比 | 排除"把趋势当结构" |
| 二级 | 与**打乱保分布**的代理序列比（打乱 r / 打乱 \|r\|） | 排除"胖尾随机游走的固有性质" |

**为什么必须两级**：真实数据在只做一级对照时通过率极高，看起来"验证成功"；
但把收益率打乱后跑同一检验，**打乱序列同样全部通过** ⇒ 这个"发现"是随机游走的固有性质，
不是真结构。只跟位移比 = **假发现**。

代码骨架：
```python
# 一级：循环位移
for shift in range(1, n):
    stat_shift = test(np.roll(x, shift))
# 二级：打乱（保分布，多次取分位）
stats_perm = [test(np.random.permutation(x)) for _ in range(1000)]
# 判定：真实统计量必须显著超过 perm 分布的高分位
```
⚠️ 打乱时注意保的是什么分布：**打乱 r 与打乱 |r| 检验的是不同的东西**，两个都要做。

## 四、纪律三：区分「文献真」与「对本项目真」

上游结论正确 ≠ 应用到这里正确。三者要分开：

| 层级 | 例子 |
|---|---|
| 文献为真 | "Transformer 在长时序预测基准上反超 CNN" |
| 推论成立 | "所以我们该换成 Transformer" ← **这一步经常塌** |
| 对本项目成立 | 需要叠加：基准测的是 MSE 还是收益？我们的样本量够吗？成本量级匹配吗？ |

**核查清单**：基准指标和我们的目标指标是同一个吗？原文的规模/成本假设与我们相同吗？
原文作者自己有没有给冷水？

## 五、双向防偏

| 偏差 | 症状 | 纠正 |
|---|---|---|
| 讨好式同意 | 「这个思路很棒」+ 直接开工 | 强制先写「不成立的部分」 |
| 为反对而反对 | 每条都要挑刺，显得深刻 | 明确写出「成立的部分」和下一步动作 |

**标准只有一个：证据。** 不是立场，也不是态度。
用户已明确授权「不客气」——有问题直接说，不要软化、不要加缓冲语。

## 六、置信度标注

- 不得把「不确定」说成「确定」（这是最常被违背的一条）。
- 置信度最好绑定可校验的东西：样本量、检验的 p 值、OOS 表现、Brier score 等。
- 三档口径：
  - **高**：有实测数据或一手文献直接支持
  - **中**：有间接证据 / 类比推理 / 单一样本
  - **低**：只有直觉或单一来源的二手说法 → 必须标注「需验证」

## 七、常见错误清单

1. 整体给一句话评价，不拆命题。
2. 只做一级对照就宣布发现。
3. 把上游文献结论直接平移到本项目，不检查假设。
4. 用"看起来很有道理"当依据。
5. 结论不带失效条件（什么情况下这条作废）。
6. 对不相干的问题给出强判定（正确但无杠杆）——
   判据是：**这个遗漏命中我们当前的绑定约束了吗？** 没命中 = 值得知道，但不改变路线。
