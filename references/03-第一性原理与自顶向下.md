# 03 · 第一性原理与自顶向下

## 一、不可颠倒的顺序

```
目标与约束  →  方法  →  执行（代码/文档/动作）
    ↑ 先定这里               ↑ 最后才到这里
```

**反了就是屎山。** 判断信号：已经开始写代码/写方案，但还说不清目标和约束。

## 二、「原理的原理」怎么找：不是找本质，是找硬约束

「第一性原理」最常见的退化，是变成一个正确但无操作性的口号：

> ❌ "这件事的本质是为了赚钱 / 为了提高效率 / 为了用户价值" —— 零操作性。

**可操作版本 = 找硬约束。**

| 类型 | 判定问句 | 例子 |
|---|---|---|
| **硬约束** | 违反它**会失败**（数学上不可能 / 物理上做不到 / 规则上不允许） | 样本量的统计下限、爆仓是吸收态、账户模式限制、手续费、司法管辖 |
| **软约束** | 违反它**只是不主流** | 行业习惯、"大家都是这么干的"、某个框架的默认写法 |

**上溯三问**（用来找到"原理的原理"）：
1. 违反这条规则会怎样？（找出后果）
2. 那个后果又由什么决定？（找出机理）
3. 拆到不能再拆，剩下的是什么？

通常收敛到四类不可再拆的量：**守恒量（能量/资金）、信息量（样本/熵）、成本、人的注意力**。

**验证是否真的找到了**：它能不能推出「所以我应该做什么 / 不应该做什么」？
推不出 = 还是口号，继续上溯。

## 三、双向对接（防空中楼阁）

自顶向下单独使用会产生**漂亮但不可实现**的方案。必须回验：

```
自顶向下：目标 → 约束 → 架构 → 方法
自底向上：数据？样本？算力？时间？成本？人？  ← 逐条回验，任一条断裂则架构作废
```

**自底向上回验清单**：

| 项 | 问句 |
|---|---|
| 数据 | 有吗？时间戳干净吗？覆盖够长吗？有前视污染吗？ |
| 样本量 | 有效样本是多少（不是原始条数）？够支撑这个参数规模吗？ |
| 算力 / 成本 | 一次迭代多少钱、多长时间？跑得起多少轮？ |
| 时间 | 最长的一段等待是多久？会不会卡住整条链？ |
| 人 | 需要谁做决定 / 提供材料？他有多久？ |
| 规则 | 账户模式、司法、平台条款允许吗？ |

## 四、绑定约束清单（必输出）

做完 P3 必须产出一张表，明确"真正卡住我们的是哪几条"：

| 编号 | 绑定约束 | 为什么它是硬的 | 怎么绕开 / 接受 |
|---|---|---|---|
| B1 | …… | 违反会…… | …… |

**这张表是后续所有决策的基准**：任何"我们应该换成 X"的主张，都必须点名它缓解了哪条绑定约束。
**点不出绑定约束的方案，不进入路线。**
