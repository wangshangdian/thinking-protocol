# 04 · 延伸方向与正规军对照库

## 第一部分 · 延伸方向

### 一、硬限额（不是为了省事，是为了不淹没主线）

| 规则 | 值 |
|---|---|
| 条数上限 | **3 条** |
| 单条长度 | **≤ 2 行** |
| 展开程度 | 「提一嘴」= 不展开论证，等追问 |
| 排序依据 | 重要性 × 可执行性；**命中绑定约束的排最前** |

超过 3 条 = 噪音。用户会一条都记不住。

### 二、单条格式

```
⭐ [延伸标题] —— 为什么重要（一句）
   最小下一步：<一个具体动作，今天就能做>
```

用 ⭐ / ⭐⭐ 标重要性（⭐⭐ = 命中绑定约束或能解锁多条后续）。

### 三、什么算「重要性高」

按优先级从高到低：

1. **命中绑定约束**——直接解开当前卡点的（最高）
2. **解锁多条后续**——做了它，后面几件事同时变简单
3. **改变了结论的方向**——不做它，当前结论可能是错的
4. **只是更好**——性能、体验、整洁度上的改进（通常不值得提）

第 4 类不要提。用户要的是杠杆，不是美化。

### 四、反面清单

- ❌ 把延伸写成愿望清单（"也可以做 A、B、C、D…"）
- ❌ 只写"还可以考虑 X"，不写为什么重要、下一步是什么
- ❌ 用延伸来回避主问题的结论
- ❌ 提了一个自己都不确定能不能做的东西

## 第二部分 · 正规军对照库

> 用途：用户提出自创方法 / 直觉 / 经验法则时，**先找官方版本**。
> 找到正式名字 = 找到全部文献 + 已知失效条件 + 可能现成的库。

### 三问法（每次执行）

1. 学术界有正式名字吗？
2. 有成熟实现 / 库吗？（先找轮子）
3. 它已知的失效条件是什么？——**正规军的边界往往正是野路子的坑**

### 对照表

| 场景 | 正规军 | 关键出处 |
|---|---|---|
| 需求澄清、把想法问清楚 | Requirements Elicitation / 用例 / BDD（Given-When-Then） / INVEST | Cockburn《Writing Effective Use Cases》；North《BDD》 |
| 值不值得花钱买更多信息 | **信息价值 VOI / EVPI / EVSI** | Howard 1966《Information Value Theory》 |
| 判断这个决定该多慎重 | **单向门 vs 双向门**（可逆性分级） | Bezos 股东信 1997/2015 |
| 小步可逆推进、逐步获取信息 | Set-based Concurrent Engineering / OODA 循环 | Ward & Sobek《Lean Product and Process Development》；Boyd |
| 找硬约束、正交分解 | **公理设计**（独立性 + 信息公理） | Suh, *Axiomatic Design* 1990/2001 |
| 找矛盾、拆冲突 | TRIZ 矛盾矩阵 | Altshuller |
| 多方案取舍 | Pugh Matrix / 设计结构矩阵 DSM | Pugh 1991 |
| 架构决策留痕 | **ADR** | Nygard 2011 |
| 实验怎么设计 | 实验设计 DOE / 因子设计 | Fisher 1935；Box, Hunter & Hunter |
| 相关 vs 因果 | **do-calculus / DAG / 潜在结果框架** | Pearl《Causality》；Rubin |
| 可证伪、防事后合理化 | 证伪主义 + **预注册** | Popper《猜想与反驳》；Nosek et al. 2018 |
| 试了很多次怎么办 | FDR 校正 / **Deflated Sharpe** / PBO | Benjamini-Hochberg 1995；Bailey & López de Prado 2014 |
| 时序数据的交叉验证 | **Purged K-Fold + Embargo** | López de Prado《Advances in Financial ML》2018 |
| 概率准不准 | Brier score / 可靠性图 / 超预测 | Brier 1950；Tetlock《Superforecasting》2016 |
| 回测好看但实盘差 | **因子样本外衰减** | McLean & Pontiff 2016, *JF* 71(1):5–32 |
| 上线后性能下降 | **PSI / KS / CUSUM / Page-Hinkley 漂移监控** | Page 1954；Sculley et al. 2015（ML 技术债） |
| 该不该滚动重训 | 滚动窗口 vs 静态 | QuantBench, arXiv:2504.18600 |
| 模型会不会讨好我 | **Constitutional AI / 红队 / steelman** | Bai et al. 2022；Anthropic red-teaming |
| 输出前自查 | **Chain-of-Verification（CoVe）** | Dhuliawala et al. 2023 |
| 工具调用循环 | ReAct / Reflexion | Yao et al. 2022；Shinn et al. 2023 |
| 复杂系统规格 | ConOps / MBSE / ISO-IEC-IEEE 15288 | 系统工程标准 |
| 知识外置、防上下文爆炸 | Zettelkasten / 原子笔记 / 第二大脑 | Luhmann；Forte《Building a Second Brain》 |
| 同一事实别写两处 | **单一事实源 SSOT** | DAMA-DMBOK |
| 自查思维偏差 | 系统 1/2、切斯特顿栅栏、幸存者偏差、锚定 | Kahneman《思考，快与慢》 |
| 分步研究、独立课题 | 工作分解结构 WBS + 阶段门（Stage-Gate） | PMI PMBOK；Cooper 1990 |

### 输出格式

```
你的做法「XXX」在学术界叫「YYY」（出处：……）。
正规军与你的差异：……
它已知的失效条件：……  ← 这条最值钱
结论：值得换成 YYY / 保留你的做法，因为……
```

### 反模式

- ❌ 为了显得专业堆术语，不给出处、不给差异
- ❌ 说"这其实就是 XXX"但答不出 XXX 的失效条件
- ❌ 把对照做成文献综述，用户只想知道"要不要换"
